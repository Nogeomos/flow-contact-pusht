### 3. 实际生效的物理参数

以下值从初始化后的仿真实例读取，并在前三条示范的碰撞回调中核对；不是仅从变量名猜测。

| 项目 | 实测值/解释 |
|---|---|
| 物体类型 | 动态刚体；mass=1，moment=3000，未标定现实 kg 或 kg·m² |
| 推杆类型 | 运动学刚体，圆半径 15；速度受 PD 指令控制，并非受力驱动机器人 |
| 物体位姿参考点 | `body.position`，即局部原点在世界的位置；不是质心 |
| 局部质心 | 实际设置为 (0,45)；几何面积质心约 (0,40.7143)，二者不同 |
| 摩擦/恢复系数 | 碰撞 Shape 的 friction/elasticity 为 0；2,380 次观测到的 arbiter 摩擦与恢复系数也为 0 |
| 阻尼/重力 | `space.damping=0`、gravity=(0,0)；直接记录系数，不称为“无阻尼” |
| 求解器 | iterations=10，collision_slop 约 0.1 |
| 时间 | 物理步长 0.01 s；控制频率 10 Hz，每动作 10 个子步 |
| PD 增益 | 位置 100、速度 20；动作是绝对目标位置 |

`body.friction=1` 在该实现中是附加在 Python body 对象上的属性，不是实际生效的 Shape 碰撞摩擦。原实现的第二块矩形惯量计算也沿用了第一块顶点；质心采用两个矩形质心的简单平均。为保留回放条件，本轮没有“修正”这些历史行为或调整参数来提高 IoU。

初始化依据原采集代码的逐示范 seed 顺序，使用 `RandomState(episode_index)` 重现初值；保留先设置位置再设置角度、reset 中推进一个物理步的旧行为。环境返回的实际状态可能不同于输入的 reset 参数，报告同时保存两者。

这提供了可检验的回放方法，但原始物体精确位姿没有独立公开字段，不能由初始化配方直接推出“逐步精确还原”。

## 发生的错误与剩余限制

1. **环境读取权限**：工具沙箱内 CIM 调用失败，原错误保留在环境报告；用 `GlobalMemoryStatusEx` 和注册表读取硬件/内存。没有因此调整系统权限。
2. **网络权限**：初次默认沙箱 HTTPS 访问产生 WinError 10013；改用获准的公开只读联网执行后，四项来源核验均成功。没有私有数据上传，也没有把首次失败写成成功下载。
3. **版本字段差异**：Pymunk distribution=6.6.0、runtime 属性=6.6.2；OpenCV distribution=4.10.0.84、runtime=4.10.0。按各自来源分别记录，不擅自更改依赖。
4. **真值限制**：原视频有损且分辨率低，物体位姿无独立真值；flow、接触和速度来自同一回放。IoU 较高与内部一致不能证明接触唯一最优。
5. **末端与终止语义**：每条示范最后动作后的状态缺少原视频帧，检查窗口排除这一终点。不能把 `next.done` 或历史末端 reward 直接当作统一成功判据。
6. **标签局限**：欧氏高斯邻域在凹角附近可能跨邻边平滑；零冲量接触不是有效推动。本轮没有评估接触点数或 sigma 的优劣。
7. **DP 未就绪部分**：仅核验官方要求与本机资源，没有安装、运行或训练 DP，没有验证默认 batch=64 的显存需求或 Windows 完整训练兼容性。

## 第二阶段建议（尚未执行）

目标是先让基础模型学会复现示范接触分布，而不是直接宣称学会最优操作。

1. **固定数据协议**：对全量示范在新目录重新验收；先按完整 episode 划分，再建 8 步窗口。可采用 164/21/21 的固定划分，但必须记录 seed、编号和哈希。测试集不用于选点数、sigma 或训练轮数。
2. **建立基础输入**：局部几何点坐标，加上从当前锚点到未来各时刻的位移。整个窗口统一转到锚点物体坐标系，不能逐帧对齐而消除运动。先用 H=8、N=64；保留“是否有接触”的显式监督，避免全零窗口主导损失。
3. **先训练小网络**：先用逐点共享 MLP 与全局几何/运动池化，输出每点每时刻的 sigmoid 分数；对软标签使用 BCE 或回归损失。sigmoid 分数是拟合标签的输出，不直接当作成功概率。先做少量样本过拟合和少数轮训练，检查梯度、损失和可视化，再扩大数据量。
4. **安排公平消融**：先固定训练协议，再分别比较 N=32/64/128、硬标签/软标签、简单时间拼接/时序编码；每次只改变一个因素。报告接触存在检测、点级误差、预测峰值到示范接触区域的距离，并单独统计有接触与无接触样本；由于多个接触可能产生类似运动，不把偏离单次示范一律等同于物理不可行。
5. **准备后续闭环接口**：离线数据可使用示范未来 flow；闭环时由当前状态和目标规划短期平移/转角，再生成期望 flow。控制器负责接近路径、方向、持续时间和重新规划，不由接触分数直接替代。
6. **DP 留到单独环境**：官方旧栈为 Linux/NVIDIA、Python 3.9、Torch 1.12.1、CUDA 11.6；先实现与本项目 episode 划分一致的数据适配，注意原 loader 期待 Zarr。先以小 batch 和少量数据加载进程测显存/内存，不自动照搬原 batch 64、8 workers、3050 epochs。确有 Windows 关键依赖不兼容证据时再讨论 WSL2/Linux，不预先改系统。
