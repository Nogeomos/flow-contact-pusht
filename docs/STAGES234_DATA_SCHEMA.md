# 第二至第四阶段的数据字段

以下说明对应 `research/contact_learning.py`、`research/evaluate_closed_loop.py` 和保存的实际样本。第一阶段逐帧物理接触字段详见 `STAGE1_DATA_SCHEMA.md`。本轮没有改写第一阶段数据。

## 共同坐标和时间约定

物体状态 `state=[agent_x, agent_y, body_origin_x, body_origin_y, theta]`。前两项是推杆实际中心，不是动作指令；中间两项是 T 形刚体局部坐标原点的世界位置，不是质心。物理质心局部坐标为 `(0,45)`。x 向右、y 向下，theta 单位为弧度；正转角在屏幕上为顺时针。世界长度是 512×512 场景中的仿真单位，不是米。

列向量公式为 `p_world=R(theta) p_local+t`，代码用行向量时写为 `p_world=p_local @ R.T+t`。世界位移转到当前物体局部坐标用 `delta_local=delta_world @ R(theta_anchor)`。

窗口锚点是执行动作前的时刻 t。H=8，控制频率 10Hz，未来窗口对应 0.8 秒，包含状态 t 到 t+8 共9帧、动作 t 到 t+7 共8个区间。只有具有视频端点且接触有效的区间可进入接触训练窗口。窗口按完整示范先划分，训练/验证/测试分别164/21/21条。

## 模型的13维几何特征

`geometry` 形状为 `[B,N,13]`，B 为窗口数、N 为轮廓点数。主模型 N=64，以下维度编号从0开始。

| 维度 | 内容 | 归一化 / 坐标 |
|---|---|---|
| 0、1 | 当前编号材料点的局部 x、y | `p_local/100` |
| 2、3 | 轮廓内法向 x、y | 局部坐标下的单位向量 |
| 4、5 | 推杆中心相对该轮廓点的局部位移 | `((agent_xy-body_origin_xy) @ R - p_local)/100` |
| 6 | 上述相对位移的欧氏距离 | 距离除以100 |
| 7、8 | 推杆实际世界坐标 x、y | `agent_xy/256-1` |
| 9、10 | 物体原点世界坐标 x、y | `body_origin_xy/256-1` |
| 11、12 | 当前角度的 cos、sin | 无长度量纲 |

轮廓顶点处取沿固定采样方向的后续边内法向。这个约定解决表示问题，不表示顶点有唯一的物理接触法向。真实碰撞法向仍来自仿真器。

13维输入包含推杆位置和绝对场景位置。因此当前表示不能称为已经验证的“完全与本体无关”表示。跨推杆几何、不同机器人和移除推杆输入的泛化实验，本轮尚未完成。

## flow、动作监督和接触监督

`flow` 形状为 `[B,N,8,2]`。在锚点 t 的局部坐标中：

```text
flow[b,n,k,:] = (p_world[t+k+1,n] - p_world[t,n]) @ R(theta[t]) / 30
```

这是累计位移，不是相邻帧差分；所有未来时刻都使用同一个锚点坐标系。除以30只是固定数值缩放，不改变长度单位。不能对每个未来帧用其自身坐标系重新对齐，否则会消除物体真实运动。

离线训练/测试中的 `p_world[t+k+1]` 来自示范回放。在线闭环调用时，同一形状的输入来自“当前状态+目标”的规划器，不能读取测试示范未来。

直接动作模型的 `action` / 样本文件中的 `action_target` 形状为 `[B,8,2]`：

```text
action_target[b,k,:] = (action_world[t+k] - agent_world[t]) @ R(theta[t]) / 100
```

基准始终是锚点的实际推杆中心，不能减去未来推杆中心。动作原始含义是推杆中心的绝对目标坐标。推理的逆变换为 `target_world=agent_world[t]+predicted_local*100 @ R(theta[t]).T`，再限制到0..512。

接触目标 `target` 形状为 `[B,N]`。它是未来8个动作周期、每周期10个物理子步中**全部有效外轮廓接触区域的并集**。对编号轮廓点计算到这些局部接触点的最小距离 d，并使用 `exp(-d²/(2*5²))`；等价于8个原始逐区间软标签逐点取最大值。没有真实接触时全零，不能把最近轮廓点强行标为正例。硬标签消融为 `d<=7.5`。

`distance` / 样本文件中的 `distance_to_future_contact` 是未经归一化的上述最小距离。无接触窗口统一填512作为缺失哨兵；不能把512解释为真实距离或将其混入正接触平均定位误差。

`presence` 表示未来8区间内是否有任一有效几何接触，不表示本时刻是否已接触，也不表示成功率。训练包含独立presence辅助输出；当前在线控制只使用逐点排序，presence head没有参与在线动作选择或停止。由于训练用了加权BCE，sigmoid输出未做概率校准，应称为分数。

## 离线模型输出 test_predictions.npz

每个接触/直接动作模型目录均保存 `test_metrics.json` 和 `test_predictions.npz`。测试窗口顺序与冻结的2,281个测试窗口清单一致。

| 字段 | 接触模型 | 直接动作模型 |
|---|---|---|
| `prediction` | `[2281,N]`逐点sigmoid分数 | `[2281,8,2]`归一化局部动作目标 |
| `presence` | `[2281]`辅助接触分数 | 空数组 |
| `distance` | `[2281,N]`真实接触距离/512哨兵 | 为统一导出保留，并非动作误差 |
| `target` | `[2281,N]`软/硬接触标签 | 为统一导出保留，并非动作监督 |
| `ids` | `[2281,2]`示范ID、锚点动作索引 | 相同 |
| `states` | `[2281,5]`锚点世界状态 | 相同 |

动作模型的实际动作误差保存在 `test_metrics.json`，不能把其`target`字段误读成动作标签。完整动作监督可由原始动作和锚点状态重建。

视觉DP的离线结果使用另一套时序：2帧输入、16步预测、实际取预测位置`[1:9]`执行8步；同示范边界padding不进入损失。`visual_dp/test_metrics.json`的`per_window`按原始数据全局anchor索引记录，完整测试为2,449帧，不与接触模型2,281个完整8步窗口混为同一统计样本集。

## 闭环执行 episode_XXXXXX.npz / JSON

每条测试至多执行T=300个动作周期。NPZ保存真实执行轨迹，不是示范回放。

| NPZ字段 | 形状 | 含义 |
|---|---|---|
| `episode_index` | 标量 | 决定初始状态的固定测试ID |
| `states` | `[T+1,5]` | 初始状态和每次实际执行后的观测 |
| `actions` | `[T,2]` | 真正传给环境的绝对推杆目标 |
| `coverage` | `[T+1]` | 物体与目标相交面积 / 目标面积，**不是IoU** |
| `contact_event_counts` | `[T]` | 每次实际动作累计的碰撞点事件数量 |
| `selected_contact_indices` | `[T]` | 接触控制器所选编号，非接触法或无可行计划时为-1 |
| `desired_flow_world` | `[T,8,64,2]` | 每一步根据新观测重新计算的诊断flow |
| `observations_rgb` | `[T+1,96,96,3]` | 实际仿真RGB观测，uint8，没有动作十字标记 |
| `goal_pose` | `[3]` | 固定目标物体原点x、y与theta |

JSON的`plans`记录每次真正重新规划的当前状态、候选点、逐点分数、**实际输入接触模型的`desired_flow_world`**、计划动作长度和候选预测统计。控制器在完整“接近+短推+保持”队列执行完才重新规划，所以一段计划内实际模型输入保持不变；不能将NPZ中每步更新的诊断flow误称为每步都重新调用了接触模型。

JSON/summary中的`success`为任一已执行状态coverage>=0.95；`native_success`另记原环境严格>0.95的规则。`final_coverage`与`max_coverage`分别是终止状态和整条轨迹最大值。候选物理预测在私有世界运行，相关`candidate_rollouts`、`candidate_physics_substeps`、耗时均与真实动作步数分开记录。

## 统计和证据边界

科学统计单位是21条独立测试初始场景。三个训练种子复用相同21场景，不能称为63个独立场景；`fresh_verification`是同权重重跑补证，也不增加样本量。no-flow追加闭环单列为事后补充诊断。

在当前世界参数和相同控制器下完成推动，不能自动证明跨本体、跨物体或真实机器人泛化。示范标签、预测分数、离线定位命中、闭环coverage及闭环成功率分别是不同含义，报告时需明确区分。
